## テストの基本概念

### テストの種類

```
┌─────────────────────────────────────────────────────┐
│                   E2Eテスト                          │  ← 少なく
│        （ブラウザ操作、システム全体）                  │
├─────────────────────────────────────────────────────┤
│              インテグレーションテスト                  │
│          （複数コンポーネントの連携）                  │
├─────────────────────────────────────────────────────┤
│                  ユニットテスト                       │  ← 多く
│            （個々のクラス・メソッド）                  │
└─────────────────────────────────────────────────────┘
              テストピラミッド
```

| テストの種類 | 対象 | 実行速度 | 数 |
|-------------|------|---------|-----|
| ユニットテスト | 個々のメソッド・クラス | 速い | 多い |
| インテグレーションテスト | コンポーネント間の連携 | 中程度 | 中程度 |
| E2Eテスト | システム全体 | 遅い | 少ない |

### テスト駆動開発（TDD）

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  Red     │ ──→ │  Green   │ ──→ │ Refactor │
│ テスト失敗│     │ テスト成功│     │ コード改善│
└──────────┘     └──────────┘     └──────────┘
     ↑                                  │
     └──────────────────────────────────┘
```

1. **Red**: 失敗するテストを書く
2. **Green**: テストを通す最小限のコードを書く
3. **Refactor**: コードを改善する（テストは通ったまま）

### BDD（振る舞い駆動開発）

```ruby
# BDDスタイル - 振る舞いを記述
describe "ユーザー登録" do
  context "有効なデータの場合" do
    it "ユーザーが作成される" do
      # ...
    end
  end

  context "無効なデータの場合" do
    it "エラーメッセージが表示される" do
      # ...
    end
  end
end
```

**🐍 Python:** `pytest` でBDD風に書く場合、`describe/context` はクラスや関数のグループ化、`it` は個々のテスト関数に対応します（`assert` 文で検証）。

```python
# BDDスタイル - 振る舞いを記述
class TestUserRegistration:
    class TestValidData:
        def test_creates_user(self):
            ...

    class TestInvalidData:
        def test_shows_error_message(self):
            ...
```

RSpecの `describe/context/it` のようなDSLを使いたい場合は `pytest-describe` や `pytest-bdd` プラグインもあります。

## Minitest（標準ライブラリ）

MinitestはRubyの標準ライブラリに含まれるテストフレームワークです。

### セットアップ

```ruby
# test/test_helper.rb
require 'minitest/autorun'
require 'minitest/pride'  # カラフルな出力（オプション）

# テスト対象のコードを読み込み
require_relative '../lib/calculator'
```

**🐍 Python:** 標準ライブラリの `unittest` がMinitestに相当します。`require 'minitest/autorun'` のような明示的な読み込みは不要で、`import unittest` してテストクラスを `unittest.TestCase` から継承します。

```python
# test_calculator.py
import unittest
from calculator import Calculator
```

### アサーションスタイル

```ruby
# test/calculator_test.rb
require_relative 'test_helper'

class CalculatorTest < Minitest::Test
  def setup
    @calculator = Calculator.new
  end

  def teardown
    # クリーンアップ処理
  end

  # テストメソッドは test_ で始める
  def test_add_two_numbers
    result = @calculator.add(2, 3)
    assert_equal 5, result
  end

  def test_subtract_two_numbers
    result = @calculator.subtract(10, 4)
    assert_equal 6, result
  end

  def test_divide_by_zero_raises_error
    assert_raises(ZeroDivisionError) do
      @calculator.divide(10, 0)
    end
  end
end
```

**🐍 Python:** `unittest.TestCase` を継承し、`setUp` / `tearDown`（キャメルケース）を定義します。テストメソッドは `test_` で始め、`assertEqual` などのメソッドで検証、例外は `assertRaises` をコンテキストマネージャとして使います。

```python
class TestCalculator(unittest.TestCase):
    def setUp(self):
        self.calculator = Calculator()

    def tearDown(self):
        pass  # クリーンアップ処理

    def test_add_two_numbers(self):
        self.assertEqual(self.calculator.add(2, 3), 5)

    def test_subtract_two_numbers(self):
        self.assertEqual(self.calculator.subtract(10, 4), 6)

    def test_divide_by_zero_raises_error(self):
        with self.assertRaises(ZeroDivisionError):
            self.calculator.divide(10, 0)
```

Rubyの `assert_equal expected, actual`（期待値が先）に対し、`assertEqual(actual, expected)` は引数順が逆でどちらを先に書いても構いません（差分表示のラベルが変わるだけ）。

### Specスタイル

```ruby
# test/calculator_spec.rb
require_relative 'test_helper'

describe Calculator do
  before do
    @calculator = Calculator.new
  end

  describe '#add' do
    it 'adds two numbers' do
      _(@calculator.add(2, 3)).must_equal 5
    end

    it 'handles negative numbers' do
      _(@calculator.add(-1, 1)).must_equal 0
    end
  end

  describe '#divide' do
    it 'divides two numbers' do
      _(@calculator.divide(10, 2)).must_equal 5
    end

    it 'raises error when dividing by zero' do
      _ { @calculator.divide(10, 0) }.must_raise ZeroDivisionError
    end
  end
end
```

**🐍 Python:** MinitestのSpecスタイル（`describe/it`）に相当するのが `pytest` です。クラス継承もアサーションメソッドも不要で、プレーンな `assert` 文だけで書けます。

```python
# test_calculator.py
import pytest
from calculator import Calculator

@pytest.fixture
def calculator():
    return Calculator()

def test_add(calculator):
    assert calculator.add(2, 3) == 5

def test_divide_by_zero(calculator):
    with pytest.raises(ZeroDivisionError):
        calculator.divide(10, 0)
```

### 主なアサーション

```ruby
# 等価性
assert_equal expected, actual          # expected == actual
refute_equal unexpected, actual        # unexpected != actual

# 真偽値
assert value                           # value が truthy
refute value                           # value が falsey
assert_nil value                       # value.nil?
refute_nil value                       # !value.nil?

# 型チェック
assert_instance_of String, value       # value.instance_of?(String)
assert_kind_of Numeric, value          # value.kind_of?(Numeric)

# 含む
assert_includes collection, item       # collection.include?(item)
assert_match /pattern/, string         # string =~ /pattern/

# 例外
assert_raises(ErrorClass) { code }     # code が ErrorClass を発生
assert_silent { code }                 # code が何も出力しない

# 出力
assert_output("expected\n") { puts "expected" }

# 差分
assert_in_delta 3.14, result, 0.01     # 浮動小数点の比較

# 空
assert_empty collection                # collection.empty?
refute_empty collection                # !collection.empty?
```

**🐍 Python:** `unittest` にも対応するアサーションメソッドがあります。`pytest` を使う場合は、これらの多くをプレーンな `assert` 文で置き換えられます。

| Minitest | unittest | pytest |
| --- | --- | --- |
| `assert_equal exp, act` | `assertEqual(act, exp)` | `assert act == exp` |
| `refute_equal exp, act` | `assertNotEqual(act, exp)` | `assert act != exp` |
| `assert value` | `assertTrue(value)` | `assert value` |
| `refute value` | `assertFalse(value)` | `assert not value` |
| `assert_nil value` | `assertIsNone(value)` | `assert value is None` |
| `assert_instance_of Cls, v` | `assertIsInstance(v, Cls)` | `assert isinstance(v, Cls)` |
| `assert_includes col, item` | `assertIn(item, col)` | `assert item in col` |
| `assert_match /re/, str` | `assertRegex(str, r"re")` | `assert re.search(r"re", str)` |
| `assert_raises(Err) { }` | `assertRaises(Err)` | `pytest.raises(Err)` |
| `assert_in_delta a, b, d` | `assertAlmostEqual(a, b)` | `assert a == pytest.approx(b)` |
| `assert_empty col` | `assertFalse(col)` | `assert not col` |

### 実行

```bash
# 全テスト実行
ruby -Itest test/calculator_test.rb

# 特定のテスト
ruby -Itest test/calculator_test.rb --name test_add_two_numbers

# パターンマッチ
ruby -Itest test/calculator_test.rb --name /add/

# Rakeタスク
rake test
```

**🐍 Python:** `unittest` は `python -m unittest`、`pytest` は `pytest` コマンドで実行します。

```bash
# unittest: ディレクトリ配下を自動検出
python -m unittest discover

# unittest: 特定のテストメソッド
python -m unittest test_calculator.TestCalculator.test_add_two_numbers

# pytest: 全テスト
pytest

# pytest: 名前でフィルタ（Minitestの --name /add/ 相当）
pytest -k add
```

## RSpec（BDDフレームワーク）

RSpecはRubyで最も広く使われているテストフレームワークです。

### セットアップ

```bash
# インストール
gem install rspec

# プロジェクト初期化
rspec --init
```

```ruby
# Gemfile
group :test do
  gem 'rspec', '~> 3.12'
end
```

### 基本構文

```ruby
# spec/calculator_spec.rb
require_relative '../lib/calculator'

RSpec.describe Calculator do
  # テスト対象のインスタンス
  let(:calculator) { Calculator.new }

  describe '#add' do
    it '2つの数を足し算する' do
      expect(calculator.add(2, 3)).to eq(5)
    end

    it '負の数も扱える' do
      expect(calculator.add(-1, 1)).to eq(0)
    end
  end

  describe '#divide' do
    context '正常な場合' do
      it '2つの数を割り算する' do
        expect(calculator.divide(10, 2)).to eq(5)
      end
    end

    context 'ゼロで割る場合' do
      it '例外を発生させる' do
        expect { calculator.divide(10, 0) }.to raise_error(ZeroDivisionError)
      end
    end
  end
end
```

**🐍 Python:** RSpecに最も近いのが `pytest` です。`RSpec.describe`/`context` はクラスや関数のグループ、`it` はテスト関数、`let(:x) { ... }` は `@pytest.fixture`、`expect(x).to eq(y)` は `assert x == y`、`expect { ... }.to raise_error(E)` は `with pytest.raises(E):` に対応します。

```python
import pytest
from calculator import Calculator

@pytest.fixture
def calculator():
    return Calculator()

class TestAdd:
    def test_adds_two_numbers(self, calculator):
        assert calculator.add(2, 3) == 5

    def test_handles_negative_numbers(self, calculator):
        assert calculator.add(-1, 1) == 0

class TestDivide:
    def test_divides_two_numbers(self, calculator):
        assert calculator.divide(10, 2) == 5

    def test_raises_on_zero(self, calculator):
        with pytest.raises(ZeroDivisionError):
            calculator.divide(10, 0)
```

### subject と let

```ruby
RSpec.describe User do
  # 暗黙のsubject（クラス名から自動生成）
  subject { User.new(name: 'Alice', age: 25) }

  # 名前付きsubject
  subject(:user) { User.new(name: 'Bob', age: 30) }

  # let（遅延評価）
  let(:valid_attributes) { { name: 'Charlie', email: 'charlie@example.com' } }

  # let!（即時評価）
  let!(:admin) { User.create(name: 'Admin', role: :admin) }

  it { is_expected.to be_valid }

  it 'has a name' do
    expect(user.name).to eq('Bob')
  end
end
```

**🐍 Python:** `pytest` のフィクスチャは `let` と同じく遅延評価で、テストが引数として要求したときに初めて生成されます。`let!`（即時評価）に相当するのは `@pytest.fixture(autouse=True)` で、明示的に要求しなくても各テスト前に実行されます。RSpecの `subject` に厳密に対応する概念はなく、通常のフィクスチャで表現します。

### context でグループ化

```ruby
RSpec.describe Order do
  let(:order) { Order.new(items: items) }

  context '商品がある場合' do
    let(:items) { [Item.new(price: 100), Item.new(price: 200)] }

    it '合計金額を計算する' do
      expect(order.total).to eq(300)
    end

    it '空ではない' do
      expect(order).not_to be_empty
    end
  end

  context '商品がない場合' do
    let(:items) { [] }

    it '合計金額は0' do
      expect(order.total).to eq(0)
    end

    it '空である' do
      expect(order).to be_empty
    end
  end
end
```

### before / after フック

```ruby
RSpec.describe Database do
  before(:all) do
    # 全テスト前に1回だけ
    DatabaseCleaner.clean_with(:truncation)
  end

  before(:each) do
    # 各テスト前
    @connection = Database.connect
  end

  after(:each) do
    # 各テスト後
    @connection.close
  end

  after(:all) do
    # 全テスト後に1回だけ
    Database.disconnect_all
  end

  # around フック
  around(:each) do |example|
    Database.transaction do
      example.run
      raise ActiveRecord::Rollback
    end
  end
end
```

**🐍 Python:** `pytest` ではフックの代わりにフィクスチャのスコープで前後処理を表現します。`before(:each)`/`after(:each)` はスコープ既定（`function`）のフィクスチャ、`before(:all)`/`after(:all)` は `scope="module"` や `scope="class"` に相当します。`yield` の前が前処理、後が後処理（`after` 相当）で、`around` フックも `yield` を挟んで自然に書けます。

```python
@pytest.fixture(scope="module", autouse=True)
def clean_database():
    DatabaseCleaner.clean()   # before(:all) 相当
    yield
    Database.disconnect_all() # after(:all) 相当

@pytest.fixture
def connection():
    conn = Database.connect() # before(:each) 相当
    yield conn
    conn.close()              # after(:each) 相当
```

### マッチャー

```ruby
# 等価性
expect(actual).to eq(expected)         # ==
expect(actual).to eql(expected)        # eql?
expect(actual).to equal(expected)      # equal?（同一オブジェクト）
expect(actual).to be(expected)         # equal?

# 比較
expect(10).to be > 5
expect(10).to be >= 10
expect(10).to be < 20
expect(10).to be_between(5, 15).inclusive

# 真偽値
expect(true).to be true
expect(false).to be false
expect(nil).to be_nil
expect(nil).to be_falsey
expect(1).to be_truthy

# 型
expect('hello').to be_a(String)
expect([]).to be_an(Array)
expect(1).to be_a_kind_of(Numeric)

# コレクション
expect([1, 2, 3]).to include(2)
expect([1, 2, 3]).to contain_exactly(3, 1, 2)  # 順序無視
expect([1, 2, 3]).to match_array([3, 1, 2])    # 同上
expect([1, 2, 3]).to start_with(1)
expect([1, 2, 3]).to end_with(3)
expect([]).to be_empty
expect([2, 4, 6]).to all(be_even)

# 文字列
expect('hello').to include('ell')
expect('hello').to start_with('he')
expect('hello').to match(/^he/)

# 例外
expect { raise 'error' }.to raise_error
expect { raise ArgumentError, 'bad' }.to raise_error(ArgumentError, /bad/)
expect { safe_op }.not_to raise_error

# 変化
expect { x += 1 }.to change { x }.by(1)
expect { user.grow }.to change(user, :age).from(20).to(21)

# 出力
expect { puts 'hello' }.to output("hello\n").to_stdout
expect { warn 'oops' }.to output(/oops/).to_stderr

# 述語（be_xxx → xxx? を呼ぶ）
expect(user).to be_valid       # user.valid?
expect(user).to be_admin       # user.admin?
expect([]).to be_empty         # [].empty?

# have_xxx → has_xxx? を呼ぶ
expect(user).to have_permission(:read)  # user.has_permission?(:read)
```

**🐍 Python:** `pytest` には専用のマッチャーDSLはなく、大半はプレーンな `assert` 文で表現します。

```python
# 等価性・比較
assert actual == expected
assert actual is expected          # equal?（同一オブジェクト）相当
assert 10 > 5

# 真偽値・None
assert value is True
assert value is None
assert bool(value)                 # be_truthy 相当

# 型
assert isinstance("hello", str)

# コレクション
assert 2 in [1, 2, 3]
assert sorted([1, 2, 3]) == sorted([3, 1, 2])  # match_array 相当
assert all(x % 2 == 0 for x in [2, 4, 6])      # all(be_even) 相当
assert not []                                   # be_empty 相当

# 文字列
assert "ell" in "hello"
assert "hello".startswith("he")
import re; assert re.search(r"^he", "hello")

# 例外
with pytest.raises(ArgumentError, match="bad"):
    ...

# 述語（be_xxx → xxx? / 属性）
assert user.is_valid()
```

RSpecの `be_valid` のような述語マッチャーはメソッド名を自動変換しますが、Pythonでは `user.is_valid()` のように明示的に呼び出す点が異なります。

```ruby
RSpec.shared_context 'authenticated user' do
```

**🐍 Python:** `shared_examples`（共有例）は `pytest` の `@pytest.mark.parametrize` や `conftest.py` に置いた共通フィクスチャで、`shared_context`（共有コンテキスト）は複数テストで再利用するフィクスチャで表現します。`conftest.py` に定義したフィクスチャはディレクトリ配下のテストから自動的に利用可能になります（`include_context` のような明示的取り込みは不要）。

## テストダブル（モック・スタブ）

外部依存を模倣するためのテストダブルについて解説します。

### 用語

| 用語 | 説明 |
|-----|------|
| ダブル | テスト用の偽オブジェクト全般 |
| スタブ | 特定の戻り値を返す |
| モック | 呼び出しを検証する |
| スパイ | 呼び出しを記録して後で検証 |
| フェイク | 簡易実装を持つ代替オブジェクト |

### RSpec でのモック・スタブ

```ruby
RSpec.describe PaymentService do
  describe '#process' do
    # ダブル（テスト用偽オブジェクト）
    let(:gateway) { instance_double(PaymentGateway) }
    let(:service) { PaymentService.new(gateway) }

    context '支払い成功' do
      before do
        # スタブ（戻り値を設定）
        allow(gateway).to receive(:charge).and_return(true)
      end

      it '成功を返す' do
        expect(service.process(100)).to be true
      end
    end

    context '支払い処理の検証' do
      it 'ゲートウェイを呼び出す' do
        # モック（呼び出しを期待）
        expect(gateway).to receive(:charge).with(100).and_return(true)

        service.process(100)
      end
    end
  end
end
```

**🐍 Python:** 標準ライブラリの `unittest.mock` を使います。`instance_double` は `Mock`/`MagicMock`（`spec=` で仕様を限定）、`allow(x).to receive(:m).and_return(v)` は `mock.m.return_value = v`、`expect(x).to receive(:m)` の検証は呼び出し後の `assert_called_with` に対応します。

```python
from unittest.mock import MagicMock

def test_process_success():
    gateway = MagicMock(spec=PaymentGateway)
    gateway.charge.return_value = True   # スタブ（戻り値を設定）

    service = PaymentService(gateway)
    assert service.process(100) is True

def test_calls_gateway():
    gateway = MagicMock(spec=PaymentGateway)
    gateway.charge.return_value = True

    PaymentService(gateway).process(100)

    # モック（呼び出しを検証） — RSpecと違い呼び出しの「後」に検証する
    gateway.charge.assert_called_once_with(100)
```

RSpecのモックは事前に期待を宣言しますが、`unittest.mock` はスパイ的に動作し、実行後に `assert_called_*` で検証するのが基本スタイルです。

### スタブの詳細

```ruby
# 基本的なスタブ
allow(object).to receive(:method).and_return(value)

# 引数に応じた戻り値
allow(object).to receive(:method).with(1).and_return('one')
allow(object).to receive(:method).with(2).and_return('two')

# 複数回の呼び出し
allow(object).to receive(:method).and_return(1, 2, 3)
# 1回目→1, 2回目→2, 3回目以降→3

# ブロックで動的な戻り値
allow(object).to receive(:method) do |arg|
  arg * 2
end

# 例外を発生
allow(object).to receive(:method).and_raise(StandardError, 'error')

# 元のメソッドを呼ぶ
allow(object).to receive(:method).and_call_original

# 何でも受け入れる
allow(object).to receive(:method).with(anything).and_return(true)
allow(object).to receive(:method).with(any_args).and_return(true)
```

**🐍 Python:** `unittest.mock` でのスタブ設定の対応です。

```python
mock = MagicMock()

# 基本的なスタブ
mock.method.return_value = value

# 引数に応じた戻り値（side_effect に関数を渡す）
mock.method.side_effect = lambda arg: "one" if arg == 1 else "two"

# 複数回の呼び出し（イテラブルを渡すと順に返す）
mock.method.side_effect = [1, 2, 3]

# 例外を発生
mock.method.side_effect = StandardError("error")

# 何でも受け入れる（引数を指定しなければ任意の引数を受ける）
mock.method.return_value = True
```

### モックの詳細

```ruby
# 呼び出しを期待
expect(object).to receive(:method)

# 引数を検証
expect(object).to receive(:method).with(1, 2, 3)
expect(object).to receive(:method).with(hash_including(key: 'value'))
expect(object).to receive(:method).with(array_including(1, 2))

# 呼び出し回数
expect(object).to receive(:method).once
expect(object).to receive(:method).twice
expect(object).to receive(:method).exactly(3).times
expect(object).to receive(:method).at_least(:once)
expect(object).to receive(:method).at_most(5).times

# 順序
expect(object).to receive(:first).ordered
expect(object).to receive(:second).ordered
```

**🐍 Python:** `unittest.mock` では実行後に検証メソッドで確認します。

```python
mock.method.assert_called()                    # 呼ばれた
mock.method.assert_called_with(1, 2, 3)        # 引数を検証
mock.method.assert_called_once()               # ちょうど1回
mock.method.assert_called_once_with(1, 2, 3)   # 1回かつ引数一致
assert mock.method.call_count == 3             # exactly(3).times 相当
mock.method.assert_not_called()                # 呼ばれていない

# 呼び出し順序の検証
from unittest.mock import call
parent = MagicMock()
parent.assert_has_calls([call.first(), call.second()])
```

### Minitest でのモック

```ruby
require 'minitest/autorun'
require 'minitest/mock'

class PaymentServiceTest < Minitest::Test
  def test_process_payment
    gateway = Minitest::Mock.new
    gateway.expect(:charge, true, [100])

    service = PaymentService.new(gateway)
    result = service.process(100)

    assert result
    gateway.verify
  end
end

# スタブ
class ExternalServiceTest < Minitest::Test
  def test_with_stub
    ExternalApi.stub(:fetch, 'stubbed response') do
      result = MyService.new.call
      assert_equal 'stubbed response', result
    end
  end
end
```

**🐍 Python:** `unittest` でも同じく `unittest.mock` を使います。Minitestの `Object.stub(:method, value) do ... end`（一時的な差し替え）に相当するのが `patch`（デコレータまたは `with` 文でスコープ内だけ差し替え）です。

```python
from unittest.mock import Mock, patch

class TestPaymentService(unittest.TestCase):
    def test_process_payment(self):
        gateway = Mock()
        gateway.charge.return_value = True

        result = PaymentService(gateway).process(100)

        self.assertTrue(result)
        gateway.charge.assert_called_once_with(100)

# スタブ（patch でスコープ内だけ差し替え）
class TestExternalService(unittest.TestCase):
    def test_with_stub(self):
        with patch.object(ExternalApi, "fetch", return_value="stubbed response"):
            self.assertEqual(MyService().call(), "stubbed response")
```

```ruby
# Gemfile
group :test do

```

```ruby
# spec/factories/users.rb
FactoryBot.define do
  factory :user do
    sequence(:email) { |n| "user#{n}@example.com" }
    name { 'Test User' }
    password { 'password123' }

    trait :admin do
      role { :admin }
    end

    trait :with_posts do
      after(:create) do |user|
        create_list(:post, 3, user: user)
      end
    end
  end

  factory :post do
    title { 'Test Post' }
    body { 'This is a test post.' }
    user
  end
end
```

```ruby
# 使用
RSpec.describe User do
  # build: インスタンス作成（保存しない）
  let(:user) { build(:user) }

  # create: 保存する
  let(:saved_user) { create(:user) }

  # 属性を上書き
  let(:admin) { create(:user, :admin, name: 'Admin User') }

  # トレイトの使用
  let(:user_with_posts) { create(:user, :with_posts) }

  # build_list / create_list
  let(:users) { create_list(:user, 5) }
end
```

**🐍 Python:** FactoryBotに相当するのが `factory_boy` です。`factory :user do` はクラス定義、`sequence` は `factory.Sequence`、`trait` は `factory.Trait`、`build`/`create` は `Factory.build()` / `Factory.create()` に対応します。

```python
import factory

class UserFactory(factory.Factory):
    class Meta:
        model = User

    email = factory.Sequence(lambda n: f"user{n}@example.com")
    name = "Test User"
    password = "password123"

    class Params:
        admin = factory.Trait(role="admin")

# 使用
user = UserFactory.build()                 # build 相当（保存しない）
saved = UserFactory.create()               # create 相当
admin = UserFactory.create(admin=True, name="Admin User")  # トレイト＋上書き
users = UserFactory.create_batch(5)        # create_list 相当
```

## テストのベストプラクティス

### 1. AAAパターン

```ruby
it 'calculates total price' do
  # Arrange（準備）
  cart = Cart.new
  cart.add_item(Item.new(price: 100))
  cart.add_item(Item.new(price: 200))

  # Act（実行）
  total = cart.total

  # Assert（検証）
  expect(total).to eq(300)
end
```

### 2. 1テスト1アサーション

```ruby
# 悪い例
it 'creates a user' do
  user = User.create(name: 'Alice', email: 'alice@example.com')
  expect(user).to be_persisted
  expect(user.name).to eq('Alice')
  expect(user.email).to eq('alice@example.com')
end

# 良い例
describe 'creating a user' do
  subject(:user) { User.create(name: 'Alice', email: 'alice@example.com') }

  it { is_expected.to be_persisted }
  it { is_expected.to have_attributes(name: 'Alice') }
  it { is_expected.to have_attributes(email: 'alice@example.com') }
end
```

### 3. 説明的なテスト名

```ruby
# 悪い例
it 'works' do
  expect(user.valid?).to be true
end

# 良い例
it 'is valid with valid attributes' do
  expect(user).to be_valid
end

it 'is invalid without an email' do
  user.email = nil
  expect(user).not_to be_valid
end
```

### 4. テストの独立性

```ruby
# 悪い例（テスト間の依存）
describe User do
  it 'creates user' do
    @user = User.create(name: 'Alice')
    expect(@user).to be_persisted
  end

  it 'updates user' do
    @user.update(name: 'Bob')  # 前のテストに依存
    expect(@user.name).to eq('Bob')
  end
end

# 良い例
describe User do
  let(:user) { create(:user, name: 'Alice') }

  it 'creates user' do
    expect(user).to be_persisted
  end

  it 'updates user' do
    user.update(name: 'Bob')
    expect(user.name).to eq('Bob')
  end
end
```

### 5. 実装ではなく振る舞いをテスト

```ruby
# 悪い例（実装の詳細に依存）
it 'stores items in @items array' do
  cart.add_item(item)
  expect(cart.instance_variable_get(:@items)).to include(item)
end

# 良い例（振る舞いをテスト）
it 'includes added item' do
  cart.add_item(item)
  expect(cart.items).to include(item)
end
```

### 6. 境界値テスト

```ruby
describe '#adult?' do

    end

  end
```
