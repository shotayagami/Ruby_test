## 1. ビューとERBテンプレート

ビューはコントローラのアクションが用意したデータ（インスタンス変数）を受け取り、レスポンスボディ（多くはHTML）を生成する層です。標準のテンプレートエンジンは **ERB**（Embedded Ruby）で、`Erubi` により処理されます。

### ERBタグの種類

```erb
<%# これはコメント。出力もRuby評価もされない %>

<% # Rubyを実行するが、結果は出力しない（制御構文などに使う） %>
<% @articles.each do |article| %>
  <p><%= article.title %></p>   <%# 評価結果をHTMLエスケープして出力 %>
<% end %>

<%= @article.title %>   <%# 出力あり（自動でHTMLエスケープされる） %>
<%== @article.title %>  <%# 出力あり（エスケープしない＝raw。原則使わない） %>
```

| タグ | 意味 |
|------|------|
| `<% ... %>` | Rubyを実行するが出力しない。`if`/`each`などの制御に使う |
| `<%= ... %>` | Rubyを実行し、結果をHTMLエスケープして出力する |
| `<%== ... %>` | 結果をエスケープせず出力する（`raw` 相当。XSSに注意） |
| `<%# ... %>` | コメント（評価も出力もされない） |
| `<%- ... %>` / `<% ... -%>` | 前後の余分な空白・改行を抑制する |

`<%= %>` と `<% %>` の使い分けが最重要です。**画面に文字列を出したいときは `<%=`**、**繰り返しや条件分岐など出力の必要がないロジックは `<%`** を使います。`<% article.title %>` のように `=` を付け忘れると何も表示されません。

### app/views の命名規約とアクションの対応

ビューはコントローラ名のディレクトリ配下に、アクション名のファイルとして置きます。ファイル名は `アクション名.フォーマット.ハンドラ` の形式です。

```
app/views/
  articles/
    index.html.erb    # ArticlesController#index に対応
    show.html.erb      # #show
    new.html.erb       # #new
    edit.html.erb      # #edit
    _form.html.erb     # パーシャル（先頭アンダースコア）
  layouts/
    application.html.erb
```

- `html` はフォーマット（`json`, `text` など）、`erb` はハンドラ（`erb`, `builder`, `jbuilder` など）です。
- コントローラのアクションで明示的に `render` を呼ばなければ、`アクション名.html.erb` が **暗黙的にレンダリング** されます。
- 別テンプレートを描画したいときは `render :edit` や `render "articles/custom"` を使います。

```ruby
class ArticlesController < ApplicationController
  def show
    @article = Article.find(params[:id])
    # 明示的な render がなければ app/views/articles/show.html.erb を描画
  end
end
```

## 2. レイアウト

レイアウトはヘッダー・フッターなど全ページ共通の骨組みを定義し、各アクションのビューを内側に埋め込みます。既定のレイアウトは `app/views/layouts/application.html.erb` です。

### application.html.erb と yield

```erb
<!-- app/views/layouts/application.html.erb -->
<!DOCTYPE html>
<html>
  <head>
    <title><%= content_for?(:title) ? yield(:title) : "My App" %></title>
    <%= csrf_meta_tags %>          <%# CSRFトークン %>
    <%= csp_meta_tag %>            <%# Content-Security-Policy %>
    <%= stylesheet_link_tag "application" %>
    <%= javascript_importmap_tags %>
  </head>
  <body>
    <%= yield %>   <%# 各アクションのビューがここに挿入される %>
  </body>
</html>
```

`yield`（引数なし）の位置に、各アクションのビュー本体が埋め込まれます。

### content_for / provide でセクションを差し込む

`content_for` はビュー側から名前付きのブロックを登録し、レイアウト側で `yield(:名前)` として取り出す仕組みです。ページ固有のタイトルやサイドバー内容を渡すのに使います。

```erb
<!-- app/views/articles/show.html.erb -->
<% content_for :title, @article.title %>

<% content_for :sidebar do %>
  <ul>
    <li><%= link_to "一覧へ", articles_path %></li>
  </ul>
<% end %>

<h1><%= @article.title %></h1>
```

```erb
<!-- レイアウト側で取り出す -->
<title><%= yield(:title) %> - My App</title>
<aside><%= yield(:sidebar) %></aside>
```

`provide` は `content_for` の仲間ですが、そのブロックで「登録が完了した」ことを示します。ストリーミング配信時に早期にフラッシュできる利点があり、主に `<title>` のような単発の値で使われます。

```erb
<% provide :title, "記事詳細" %>   <%# content_for と違い蓄積せず、その場で確定 %>
```

| メソッド | 役割 |
|----------|------|
| `yield` | アクションのビュー本体を挿入する |
| `yield(:name)` | 名前付きで登録された内容を取り出す |
| `content_for(:name) { ... }` | 内容を登録する（複数回呼ぶと連結される） |
| `content_for?(:name)` | その名前の内容が登録済みか判定する |
| `provide(:name, value)` | content_for の亜種。蓄積せず確定させる（ストリーミング向き） |

### 複数レイアウトと layout 指定

コントローラで `layout` を宣言すると、既定の `application` 以外のレイアウトを使えます。

```ruby
class Admin::BaseController < ApplicationController
  layout "admin"              # このコントローラ配下は admin.html.erb を使う
end

class ArticlesController < ApplicationController
  layout "print", only: :show # show アクションだけ print レイアウト
  layout false, only: :feed   # feed はレイアウトなし

  def custom
    render layout: "special"  # アクション単位で指定することも可能
  end
end
```

- `layout "名前"` … 使用するレイアウトを指定。
- `layout :method_name` … シンボルを渡すとメソッドの戻り値で動的に決定。
- `layout false` … レイアウトを無効化。
- レイアウトファイルは `app/views/layouts/` に置きます。

## 3. パーシャル

パーシャル（部分テンプレート）は、ビューの一部を切り出して再利用するための仕組みです。ファイル名は先頭にアンダースコアを付けます（例: `_form.html.erb`）が、呼び出すときはアンダースコアを付けません。

### 基本的な呼び出し

```erb
<%= render "form" %>            <%# app/views/articles/_form.html.erb を描画 %>
<%= render "shared/header" %>   <%# app/views/shared/_header.html.erb を描画 %>

<%# 明示的な書き方（partial: 指定） %>
<%= render partial: "form" %>
```

`new.html.erb` と `edit.html.erb` で共通のフォームを `_form.html.erb` に切り出すのは、Railsのscaffoldでも採用される定番パターンです。

```erb
<!-- app/views/articles/new.html.erb -->
<h1>新規記事</h1>
<%= render "form", article: @article %>

<!-- app/views/articles/edit.html.erb -->
<h1>記事の編集</h1>
<%= render "form", article: @article %>
```

### locals で値を渡す

パーシャルへローカル変数を渡すには `locals:` を使います。省略記法として `render "form", article: @article` のようにキーを直接並べることもできます。

```erb
<%# 明示的な locals 指定 %>
<%= render partial: "article", locals: { article: @article, highlight: true } %>

<%# 省略記法（上と同じ意味） %>
<%= render "article", article: @article, highlight: true %>
```

```erb
<!-- app/views/articles/_article.html.erb -->
<article class="<%= "is-highlight" if highlight %>">
  <h2><%= article.title %></h2>
</article>
```

### コレクションのレンダリング

配列やリレーションを渡すと、要素ごとにパーシャルが繰り返し描画されます。パーシャル内ではファイル名と同じ名前のローカル変数（`article`）で各要素を参照できます。

```erb
<%# 完全形: partial と collection を指定 %>
<%= render partial: "article", collection: @articles %>

<%# 短縮形: モデル名からパーシャルを自動推測して _article を各要素に適用 %>
<%= render @articles %>
```

`render @articles` は、要素のクラス（`Article`）から `articles/_article` を自動で選び、各要素を `article` というローカル変数で渡します。コレクションレンダリングは1件ずつ `render` を呼ぶより高速です。

繰り返し内では、`article_counter`（0始まりの連番）や `article_iteration`（`first?`/`last?`/`index`/`size` を持つオブジェクト）が自動で使えます。

```erb
<!-- _article.html.erb -->
<li class="<%= "first" if article_iteration.first? %>">
  <%= article_counter + 1 %>. <%= article.title %>
</li>
```

### spacer_template（区切りの挿入）

要素と要素の間に区切り用パーシャルを挟みたいときは `spacer_template:` を使います。

```erb
<%= render partial: "article", collection: @articles, spacer_template: "article_divider" %>
```

```erb
<!-- app/views/articles/_article_divider.html.erb -->
<hr class="divider">
```

| 書き方 | 説明 |
|--------|------|
| `render "form"` | 同ディレクトリの `_form.html.erb` を描画 |
| `render partial: "article", locals: {...}` | ローカル変数を渡して描画 |
| `render partial: "article", collection: @articles` | コレクションを1件ずつ描画 |
| `render @articles` | クラスからパーシャルを推測して繰り返し描画 |
| `spacer_template:` | 各要素の間に挟む区切りパーシャル |

## 4. ビューヘルパー

ヘルパーはビューでよく使う処理をメソッド化した部品です。Railsは多数の組み込みヘルパーを提供します。

### 主なリンク・タグ系ヘルパー

```erb
<%= link_to "記事一覧", articles_path %>
<%= link_to "編集", edit_article_path(@article), class: "btn" %>
<%= link_to @article.title, @article %>   <%# モデルを渡すと show へのパス %>

<%# DELETEなど非GETは button_to を使う（Turboが method を扱う） %>
<%= button_to "削除", @article, method: :delete, data: { turbo_confirm: "本当に削除しますか？" } %>

<%= image_tag "logo.png", alt: "ロゴ", size: "120x40" %>
<%= url_for(@article) %>   <%# パス文字列を生成 %>
```

### フォーマット・テキスト系ヘルパー

```erb
<%= number_to_currency(1980) %>          <%# "$1,980.00"（ロケール依存） %>
<%= number_with_delimiter(1234567) %>    <%# "1,234,567" %>
<%= truncate("長い本文...", length: 20) %>   <%# 20文字で切り詰め「...」付き %>
<%= pluralize(3, "comment") %>           <%# "3 comments" %>
<%= time_ago_in_words(@article.created_at) %>  <%# "about 2 hours"（○前に整形） %>
```

### よく使うヘルパー一覧

| ヘルパー | 用途 |
|----------|------|
| `link_to(text, path, options)` | `<a>` タグを生成（GETリンク） |
| `button_to(text, path, method:)` | フォームを内包したボタン。DELETE/POSTに使う |
| `image_tag(src, options)` | `<img>` タグを生成（アセットパスを解決） |
| `url_for(options)` | パス／URL文字列を生成 |
| `number_to_currency(n)` | 通貨表記に整形 |
| `number_with_delimiter(n)` | 桁区切りを挿入 |
| `truncate(text, length:)` | 文字列を指定長で切り詰める |
| `pluralize(count, word)` | 数に応じて単数／複数形にする |
| `time_ago_in_words(time)` | 「○分前」相当の相対表現に整形 |
| `distance_of_time_in_words(a, b)` | 2時刻の差を言葉で表現 |
| `simple_format(text)` | 改行を `<br>` / `<p>` に変換 |
| `content_tag(:div, text)` / `tag.div(text)` | 任意のHTMLタグを生成 |
| `mail_to("a@example.com")` | mailto リンクを生成 |
| `sanitize(html)` | 危険なタグを除去してHTMLを出力 |

### 自作ヘルパー（app/helpers）

共通の表示ロジックは `app/helpers` にヘルパーメソッドとして定義します。ヘルパーモジュールのメソッドはすべてのビューから利用できます。

```ruby
# app/helpers/articles_helper.rb
module ArticlesHelper
  # 公開状態をバッジ表示する
  def status_badge(article)
    label = article.published? ? "公開" : "下書き"
    css   = article.published? ? "badge-green" : "badge-gray"
    content_tag(:span, label, class: css)
  end
end
```

```erb
<%= status_badge(@article) %>
```

## 5. form_with によるフォーム

`form_with` はRails 5.1で導入された統一的なフォームヘルパーで、現在の標準です。古い `form_for` / `form_tag`（非推奨/旧来）の役割を1つに統合しています。

### モデル指定とURL指定

```erb
<%# モデル指定: パスとHTTPメソッド、フィールドのnameを自動決定 %>
<%= form_with model: @article do |f| %>
  <%= f.text_field :title %>
  <%= f.submit %>
<% end %>

<%# URL指定: 検索フォームなどモデルに紐づかない場合 %>
<%= form_with url: search_path, method: :get do |f| %>
  <%= f.text_field :q %>
  <%= f.submit "検索" %>
<% end %>
```

`model:` を渡すと、新規レコード（`new_record?`）なら `POST /articles`、永続化済みなら `PATCH /articles/:id` へ送信するフォームが自動生成されます。フィールドの `name` 属性も `article[title]` の形で自動設定され、`params[:article][:title]` として受け取れます。

### scope とネームスペース

`scope:` は、URL指定のフォームでパラメータのグループ名を指定します。`model:` と併用してネストされたリソースを扱うこともできます。

```erb
<%# params[:search][:q] として送信される %>
<%= form_with url: search_path, scope: :search, method: :get do |f| %>
  <%= f.text_field :q %>
<% end %>

<%# ネストしたリソース: /articles/1/comments へ POST %>
<%= form_with model: [@article, @comment] do |f| %>
  <%= f.text_area :body %>
<% end %>
```

### local / Turbo との関係

Rails 7/8ではHotwireのTurboが標準で有効なため、`form_with` が生成するフォームの送信は既定でTurbo Driveが横取りし、非同期的に処理されます。従来の `local:` オプションでフォーム送信の挙動を切り替えていましたが、現在はTurboを無効化したいとき `data: { turbo: false }` を使うのが標準です。

```erb
<%# このフォームだけTurboを無効化し、通常のフルページ遷移にする %>
<%= form_with model: @article, data: { turbo: false } do |f| %>
  ...
<% end %>
```

### フィールドビルダのメソッド

ブロック引数 `f`（フォームビルダ）を通じて、各種入力フィールドを生成します。

```erb
<%= form_with model: @article do |f| %>
  <%= f.label :title %>
  <%= f.text_field :title %>
  <%= f.text_area :body, rows: 8 %>

  <%# 静的な選択肢 %>
  <%= f.select :category, %w[技術 日記 お知らせ], include_blank: "選択してください" %>

  <%# DBのレコードから選択肢を作る %>
  <%= f.collection_select :author_id, Author.all, :id, :name %>

  <%= f.check_box :published %>
  <%= f.radio_button :status, "draft" %>
  <%= f.radio_button :status, "published" %>

  <%= f.date_field :published_on %>
  <%= f.number_field :view_count %>
  <%= f.hidden_field :token %>

  <%= f.submit "保存" %>
<% end %>
```

| メソッド | 生成される入力 |
|----------|----------------|
| `f.label :title` | `<label>` |
| `f.text_field :title` | `<input type="text">` |
| `f.text_area :body` | `<textarea>` |
| `f.select :category, choices` | `<select>`（選択肢を配列/ハッシュで指定） |
| `f.collection_select :author_id, Author.all, :id, :name` | レコード集合から `<select>` を生成 |
| `f.check_box :published` | `<input type="checkbox">`（隠しフィールド付き） |
| `f.radio_button :status, "draft"` | `<input type="radio">` |
| `f.date_field :published_on` | `<input type="date">` |
| `f.number_field :view_count` | `<input type="number">` |
| `f.hidden_field :token` | `<input type="hidden">` |
| `f.email_field` / `f.password_field` / `f.file_field` | 各種HTML5入力 |
| `f.submit "保存"` | 送信ボタン。省略時はモデル名から文言を自動生成 |

`collection_select` の引数は `(メソッド名, コレクション, 値のメソッド, 表示のメソッド)` の順です。`f.check_box` は、未チェック時にも値を送るための隠しフィールドを自動で併せて出力します。

## 6. フォームのエラー表示

モデルのバリデーションに失敗すると、`object.errors` にエラー情報が蓄積されます。ビューではこれを読み出してユーザーに提示します。

```erb
<%= form_with model: @article do |f| %>
  <% if @article.errors.any? %>
    <div class="error-explanation">
      <h2><%= pluralize(@article.errors.count, "件") %>のエラーがあります</h2>
      <ul>
        <% @article.errors.full_messages.each do |message| %>
          <li><%= message %></li>   <%# 例: "Title を入力してください" %>
        <% end %>
      </ul>
    </div>
  <% end %>

  <%= f.label :title %>
  <%= f.text_field :title %>
  <%= f.submit %>
<% end %>
```

| 呼び出し | 内容 |
|----------|------|
| `object.errors.any?` | エラーが1件以上あるか |
| `object.errors.count` | エラー件数 |
| `object.errors.full_messages` | 属性名を含む完全なメッセージ配列 |
| `object.errors[:title]` | 特定属性のメッセージ配列 |
| `object.errors.full_messages_for(:title)` | 特定属性の完全メッセージ配列 |

### エラー時のフィールドラッパ

バリデーションエラーのあるフィールドは、Railsが自動的に `<div class="field_with_errors">` で包みます。これを利用してCSSでハイライトできます。

```erb
<%= f.text_field :title %>
<%# エラー時の生成例: %>
<%# <div class="field_with_errors"><input type="text" ...></div> %>
```

```ruby
# ラッパのHTMLはカスタマイズ可能（config/initializers/ などで設定）
config.action_view.field_error_proc = proc do |html_tag, instance|
  content_tag(:div, html_tag, class: "has-error")
end
```

## 7. flashメッセージの表示

flashはリクエストをまたいで（主にリダイレクト後に）一度だけ表示するメッセージを保持する仕組みです。コントローラでセットし、ビューで表示します。

```ruby
class ArticlesController < ApplicationController
  def create
    @article = Article.new(article_params)
    if @article.save
      redirect_to @article, notice: "記事を作成しました"   # flash[:notice] のショートカット
    else
      flash.now[:alert] = "保存に失敗しました"              # 同一リクエスト内で表示（renderと併用）
      render :new, status: :unprocessable_entity
    end
  end
end
```

```erb
<!-- レイアウトなど共通箇所で全flashを表示 -->
<% flash.each do |type, message| %>
  <div class="flash flash-<%= type %>"><%= message %></div>
<% end %>
```

- `redirect_to ..., notice:` / `alert:` は `flash[:notice]` / `flash[:alert]` の短縮記法です。
- `flash.now[...]` はリダイレクトせず同じリクエストで `render` するときに使います（次のリクエストには持ち越されません）。
- 任意のキー（`flash[:success]` など）も使えます。

## 8. HTMLエスケープと html_safe / sanitize / raw

Railsのビューでは、`<%= %>` で出力される文字列は **自動的にHTMLエスケープ** されます。これがXSS（クロスサイトスクリプティング）に対する基本防御です。

```erb
<%# ユーザー入力に <script> が含まれても、そのまま文字として表示され実行されない %>
<%= "<script>alert('xss')</script>" %>
<%# 出力: &lt;script&gt;alert(&#39;xss&#39;)&lt;/script&gt; %>
```

| メソッド | 挙動 | 安全性 |
|----------|------|--------|
| （既定の `<%= %>`） | HTMLエスケープして出力 | 安全 |
| `html_safe` | 「エスケープ済み」と印を付けてそのまま出力 | 危険（信頼できる文字列のみ） |
| `raw(str)` | `html_safe` 相当。エスケープせず出力 | 危険 |
| `sanitize(str)` | 許可タグ以外を除去して安全化してから出力 | 比較的安全 |
| `strip_tags(str)` | すべてのHTMLタグを除去 | 安全 |

```erb
<%# 危険: ユーザー入力に html_safe / raw を使ってはいけない %>
<%= @user_input.html_safe %>   <%# NG %>
<%= raw @user_input %>         <%# NG %>

<%# 安全: 許可したタグだけ通す %>
<%= sanitize(@user_comment, tags: %w[b i a], attributes: %w[href]) %>

<%# タグを完全に除去したいとき %>
<%= strip_tags(@user_comment) %>
```

原則として、`html_safe` / `raw` はアプリ内で生成した信頼できる文字列にのみ使い、ユーザー由来のデータには `sanitize` を使います。リッチテキストを扱う場合はAction Text（`rich_text_area` と `trix`）の利用が安全です。

## 9. アセット（Propshaft / importmap）

Rails 8の新規アプリは、CSS/画像などの静的アセットを **Propshaft** で配信します（従来は Sprockets）。JavaScriptは既定で **importmap-rails** を用い、バンドラなしでESモジュールを読み込みます。

| 仕組み | 役割 |
|--------|------|
| Propshaft | 軽量なアセットパイプライン。ダイジェスト付きパスの解決が中心（Rails 8既定） |
| Sprockets | 旧来のアセットパイプライン。結合・圧縮・トランスパイルを担う |
| importmap-rails | `bin/importmap` で管理。JSをバンドルせずブラウザのimport mapで読み込む |
| jsbundling-rails | esbuild / Bun / Rollup でJSをバンドルしたい場合の選択肢 |

### アセット系ヘルパー

```erb
<%= stylesheet_link_tag "application" %>       <%# app/assets などのCSSを読み込む %>
<%= javascript_importmap_tags %>               <%# importmap構成のJSを読み込む %>
<%= javascript_include_tag "custom" %>         <%# 個別のJSファイルを読み込む(旧来/バンドル構成) %>

<%= image_tag "logo.png", alt: "ロゴ" %>        <%# ダイジェスト付きパスを解決 %>
<%= asset_path("logo.png") %>                  <%# アセットのパス文字列を返す %>
<%= image_path("logo.png") %>                  <%# 画像用のパス文字列 %>
```

これらのヘルパーは、本番環境でファイル内容に基づくダイジェスト（フィンガープリント）付きのパスを生成し、キャッシュ制御を可能にします。

## 10. Hotwire（Turbo / Stimulus）の概要

Hotwireは、JavaScriptを最小限に抑えつつSPAに近い体験を実現するRails標準のフロントエンド技術群です。**Turbo** と **Stimulus** から成ります。

| 技術 | 概要 |
|------|------|
| Turbo Drive | リンク・フォーム送信を横取りし、`<body>` を差し替えてフルリロードを避け高速化する |
| Turbo Frames | ページの一部（`turbo_frame_tag` で囲んだ領域）だけを独立して更新する |
| Turbo Streams | サーバーからのレスポンスやWebSocketで、要素の追加・更新・削除を部分的に反映する |
| Stimulus | HTMLの `data-controller` などに紐づく軽量JSフレームワーク。DOM操作を整理する |

```erb
<%# Turbo Frame: この枠内のリンク/フォームは枠内だけを更新する %>
<%= turbo_frame_tag "article_form" do %>
  <%= render "form", article: @article %>
<% end %>

<%# Stimulus: hello コントローラを要素に結びつける %>
<div data-controller="hello">
  <input data-hello-target="name" type="text">
  <button data-action="click->hello#greet">挨拶</button>
</div>
```

Turbo Streamsはコントローラで `respond_to` の `format.turbo_stream` として応答し、`app/views/.../create.turbo_stream.erb` などのテンプレートで `turbo_stream.append` などのアクションを記述します。

## 11. 部分キャッシュ cache

`cache` ヘルパーはビューの一部（フラグメント）をキャッシュし、再描画コストを削減します。キーにモデルを渡すと、`updated_at` を含むキャッシュキーが自動生成され、レコード更新時に自然に無効化されます。

```erb
<%# @article が更新されるまで、この中の描画結果をキャッシュから返す %>
<% cache @article do %>
  <article>
    <h2><%= @article.title %></h2>
    <p><%= @article.body %></p>
  </article>
<% end %>

<%# 条件付きキャッシュ %>
<% cache_if user_signed_in?, @article do %>
  ...
<% end %>
```

コレクションでは、各要素のパーシャルをまとめてキャッシュする **collection caching** が使えます。

```erb
<%# 各 _article パーシャルの結果を要素ごとにキャッシュ %>
<%= render partial: "article", collection: @articles, cached: true %>
```

キャッシュが入れ子になった場合、外側のキャッシュキーは内側の内容にも依存する **ロシアンドール・キャッシュ** として機能します。キャッシュストア（`config.cache_store`）はメモリやRedis、`solid_cache` などを利用できます。
