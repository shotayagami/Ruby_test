## 1. 基本的なデバッグ手法

### puts / p / pp

```ruby
# puts: 文字列として出力
puts user        # => #<User:0x00007f...>
puts "Value: #{value}"

# p: inspect形式で出力（デバッグ向け）
p user           # => #<User:0x00007f... @name="Alice", @age=25>
p [1, 2, 3]      # => [1, 2, 3]

# pp: 整形出力（Pretty Print）
require 'pp'  # Ruby 2.5以降は不要
pp complex_hash  # ネストしたハッシュを見やすく表示

# 比較
data = { name: "Alice", details: { age: 25, city: "Tokyo" } }
puts data  # => {:name=>"Alice", :details=>{:age=>25, :city=>"Tokyo"}}
p data     # => {:name=>"Alice", :details=>{:age=>25, :city=>"Tokyo"}}
pp data
# {:name=>"Alice",
#  :details=>{:age=>25, :city=>"Tokyo"}}
```

**🐍 Python:**

```python
# print(): 通常の文字列表現（Rubyのputs相当）
print(user)                    # __str__ を使う
print(f"Value: {value}")

# repr(): デバッグ向けの表現（Rubyのp / inspect相当）
print(repr(user))              # __repr__ を使う
print(repr([1, 2, 3]))         # => [1, 2, 3]

# pprint.pprint(): 整形出力（Rubyのpp相当）
from pprint import pprint
data = {"name": "Alice", "details": {"age": 25, "city": "Tokyo"}}
pprint(data)
```

Rubyの `p obj` は戻り値がそのオブジェクトなので式の途中に差し込めますが、Pythonの `print()` は `None` を返します。`inspect` に相当するのは組み込みの `repr()` です。

### オブジェクトの調査

```ruby
# クラスと祖先
obj.class                # => User
obj.class.ancestors      # => [User, Object, Kernel, BasicObject]

# メソッド一覧
obj.methods              # すべてのメソッド
obj.methods - Object.methods  # 固有のメソッド
obj.public_methods
obj.private_methods
obj.protected_methods

# インスタンス変数
obj.instance_variables   # => [:@name, :@age]
obj.instance_variable_get(:@name)

# 特定のメソッドを持つか
obj.respond_to?(:save)   # => true

# メソッドの情報
method_obj = obj.method(:save)
method_obj.source_location  # => ["user.rb", 42]
method_obj.parameters       # => [[:req, :force]]
```

**🐍 Python:**

```python
# クラスと祖先
type(obj)                 # => <class 'User'>  （Rubyの obj.class 相当）
type(obj).__mro__         # メソッド解決順（Rubyの ancestors 相当）

# 属性・メソッド一覧
dir(obj)                  # 属性とメソッド一覧（Rubyの methods 相当）
vars(obj)                 # インスタンス属性の辞書（Rubyの instance_variables 相当）

# 型判定
isinstance(obj, User)     # Rubyの obj.is_a?(User) 相当
hasattr(obj, "save")      # Rubyの obj.respond_to?(:save) 相当

# メソッドの情報
import inspect
inspect.getsourcefile(obj.save)   # 定義ファイル（source_location 相当）
inspect.signature(obj.save)       # 引数情報（parameters 相当）
```

> **🐍 Python:** `isinstance(x, C)`（`x.is_a?(C)` 相当）、`type(x)`（`x.class` 相当）、`dir(x)`（`x.methods` 相当）。

### `__FILE__` と `__LINE__`

```ruby
# 現在のファイルと行番号
puts "#{__FILE__}:#{__LINE__}"

# デバッグ出力
def debug_here
  puts "Debug at #{caller.first}"
end

# トレース
def trace(message)
  location = caller.first
  puts "[TRACE] #{location}: #{message}"
end

trace("Processing started")
```

> **🐍 Python:** `__file__` と `import inspect; inspect.currentframe().f_lineno`（`__FILE__` / `__LINE__` 相当）。

### caller（コールスタック）

```ruby
def method_a
  method_b
end

def method_b
  method_c
end

def method_c
  puts caller
  # => ["file.rb:6:in `method_b'",
  #     "file.rb:2:in `method_a'",
  #     "file.rb:15:in `<main>'"]

  puts caller(1, 3)  # 1番目から3つ
  puts caller_locations  # より詳細な情報
end
```

**🐍 Python:**

```python
import traceback

def method_c():
    # 現在のコールスタックを文字列で取得（Rubyの caller 相当）
    traceback.print_stack()
    # またはリストとして取得
    frames = traceback.extract_stack()
```

Rubyの `caller` は呼び出し元より上のフレームを返しますが、Pythonの `traceback.extract_stack()` は現在のフレームを含みます。

## 2. IRB と Pry

### IRB（Interactive Ruby）

```bash
# 起動
irb

# オプション
irb --simple-prompt  # シンプルなプロンプト
irb -r my_lib        # ライブラリを読み込んで起動
```

```ruby
# IRB内での操作
irb> 1 + 1
=> 2

# 最後の結果を参照
irb> _ * 10
=> 20

# ヘルプ
irb> help

# 複数行入力
irb> def hello
irb>   puts "Hello"
irb> end
=> :hello
```

### binding.irb

```ruby
# コード内にブレークポイントを設置
def complex_calculation(x, y)
  result = x * y
  binding.irb  # ここで実行が止まる
  result + 10
end

complex_calculation(5, 3)
# IRBが起動し、result や x, y を確認できる
```

**🐍 Python:**

```python
def complex_calculation(x, y):
    result = x * y
    breakpoint()      # ここで実行が止まる（Python 3.7+、pdbが起動）
    return result + 10

# 3.6以前や明示したい場合:
#   import pdb; pdb.set_trace()
# IPythonの対話環境を埋め込みたい場合（Rubyの binding.irb / pry に近い）:
#   import IPython; IPython.embed()

complex_calculation(5, 3)
```

`breakpoint()` は標準の `pdb` を起動します。IRB/PryのようなリッチなREPLが欲しい場合は `IPython.embed()` が近い体験になります。

### Pry（高機能REPL）

```bash
# インストール
gem install pry pry-byebug

# 起動
pry
```

```ruby
# コード内でブレークポイント
def process(data)
  binding.pry  # ここで停止
  transform(data)
end

# Pryのコマンド
pry> ls              # メソッドと変数一覧
pry> ls user         # オブジェクトの詳細
pry> cd user         # コンテキストを移動
pry> cd ..           # 戻る
pry> show-source User#save  # ソースコード表示
pry> show-doc Array#map     # ドキュメント表示
pry> edit User#save  # エディタで開く
pry> whereami        # 現在位置を表示
pry> exit            # 終了
```

### Pry-byebug（ステップ実行）

```ruby
require 'pry-byebug'

def calculate
  a = 10
  binding.pry
  b = 20
  c = a + b
  c
end

# コマンド
pry> next        # 次の行へ（ステップオーバー）
pry> step        # メソッド内に入る（ステップイン）
pry> continue    # 続行
pry> finish      # 現在のメソッドを抜ける
pry> break 25    # 25行目にブレークポイント
pry> break User#save  # メソッドにブレークポイント
pry> break --delete 1  # ブレークポイント削除
```

## 3. デバッガ（debug gem）

### 基本的な使い方（Ruby 3.1+標準）

```ruby
require 'debug'

def calculate(x, y)
  debugger  # ブレークポイント
  result = x + y
  result * 2
end

calculate(3, 4)
```

**🐍 Python:** 標準ライブラリの `pdb` が debug gem に相当します。

```python
import pdb

def calculate(x, y):
    pdb.set_trace()   # ブレークポイント（3.7+なら breakpoint() でも可）
    result = x + y
    return result * 2

calculate(3, 4)

# コマンドラインからスクリプト全体をデバッグ実行（Rubyの rdbg script.rb 相当）:
#   python -m pdb script.py
```

### コマンドラインから起動

```bash
# スクリプトをデバッグモードで実行
rdbg script.rb

# 特定の行で停止
rdbg -c script.rb

# リモートデバッグ
rdbg --open script.rb
```

### デバッガコマンド

```text
# 実行制御
n, next        # 次の行（ステップオーバー）
s, step        # ステップイン
c, continue    # 続行
finish         # 現在のフレームを抜ける
q, quit        # 終了

# ブレークポイント
b, break       # ブレークポイント設定
b 10           # 10行目
b method_name  # メソッド
b file.rb:10   # ファイルと行
delete 1       # ブレークポイント削除
info b         # ブレークポイント一覧

# 情報表示
l, list        # ソースコード表示
bt, backtrace  # バックトレース
info locals    # ローカル変数
info ivars     # インスタンス変数
p expression   # 式を評価
pp expression  # Pretty print

# フレーム移動
up             # 上のフレームへ
down           # 下のフレームへ
frame 2        # 特定のフレームへ

# ウォッチ
watch @variable  # 変数の変更を監視
```

**🐍 Python:** `pdb` のコマンドはdebug gemとほぼ共通です。

```text
# 実行制御
n, next        # 次の行（ステップオーバー）
s, step        # ステップイン
c, continue    # 続行
r, return      # 現在の関数を抜ける（Rubyの finish 相当）
q, quit        # 終了

# ブレークポイント
b, break       # ブレークポイント設定
b 10           # 10行目
b file.py:10   # ファイルと行
tbreak         # 一時ブレークポイント
cl, clear 1    # ブレークポイント削除（Rubyの delete 相当）

# 情報表示
l, list        # ソースコード表示
w, where       # バックトレース（Rubyの bt 相当）
a, args        # 引数を表示
p expression   # 式を評価
pp expression  # Pretty print

# フレーム移動
u, up          # 上のフレームへ
d, down        # 下のフレームへ
```

`n / s / c / p / q` はdebug gemとほぼ同じです。「関数を抜ける」はRubyの `finish` に対しpdbでは `r`（return）、「バックトレース」は `bt` に対し `w`（where）を使います。

## 4. ログ出力

### Logger クラス

```ruby
require 'logger'

# 基本的な使い方
logger = Logger.new(STDOUT)
logger.level = Logger::DEBUG

logger.debug "デバッグ情報"
logger.info "一般的な情報"
logger.warn "警告"
logger.error "エラー"
logger.fatal "致命的なエラー"

# ファイルに出力
logger = Logger.new('app.log')
logger = Logger.new('app.log', 'daily')   # 日次ローテーション
logger = Logger.new('app.log', 10, 1024000)  # 10ファイル、1MBごと
```

**🐍 Python:** 標準ライブラリの `logging` が `Logger` に相当します。

```python
import logging

# 基本的な使い方
logger = logging.getLogger(__name__)
logger.setLevel(logging.DEBUG)
logger.addHandler(logging.StreamHandler())  # 標準エラー出力へ

logger.debug("デバッグ情報")
logger.info("一般的な情報")
logger.warning("警告")          # RubyのwarnはPythonではwarning
logger.error("エラー")
logger.critical("致命的なエラー")  # Rubyのfatal相当

# ファイルに出力（ローテーション付き）
from logging.handlers import RotatingFileHandler, TimedRotatingFileHandler
logger.addHandler(RotatingFileHandler("app.log", maxBytes=1024000, backupCount=10))
logger.addHandler(TimedRotatingFileHandler("app.log", when="midnight"))  # 日次
```

レベルは `DEBUG / INFO / WARNING / ERROR / CRITICAL` です。Rubyの `warn` は `warning`、`fatal` は `critical` に対応します。

### カスタムフォーマット

```ruby
logger = Logger.new(STDOUT)

logger.formatter = proc do |severity, datetime, progname, msg|
  "[#{datetime.strftime('%Y-%m-%d %H:%M:%S')}] #{severity}: #{msg}\n"
end

# 出力例: [2024-01-15 10:30:45] INFO: User logged in
```

**🐍 Python:**

```python
import logging

handler = logging.StreamHandler()
handler.setFormatter(logging.Formatter(
    "[%(asctime)s] %(levelname)s: %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
))
logger.addHandler(handler)
# 出力例: [2024-01-15 10:30:45] INFO: User logged in
```

### 構造化ログ

```ruby
require 'json'

class JsonLogger
  def initialize(output = STDOUT)
    @logger = Logger.new(output)
    @logger.formatter = method(:format_json)
  end

  def info(message, **context)
    @logger.info({ message: message, **context })
  end

  def error(message, exception: nil, **context)
    data = { message: message, **context }
    if exception
      data[:error_class] = exception.class.name
      data[:error_message] = exception.message
      data[:backtrace] = exception.backtrace&.first(5)
    end
    @logger.error(data)
  end

  private

  def format_json(severity, time, progname, msg)
    {
      timestamp: time.iso8601,
      level: severity,
      **msg
    }.to_json + "\n"
  end
end

# 使用
logger = JsonLogger.new
logger.info("User created", user_id: 123, email: "user@example.com")
logger.error("Failed to save", exception: e, user_id: 123)
```

### タグ付きログ

```ruby
class TaggedLogger
  def initialize(logger)
    @logger = logger
    @tags = []
  end

  def tagged(*tags)
    @tags.concat(tags)
    yield self
  ensure
    @tags.pop(tags.size)
  end

  def info(message)
    @logger.info(format_with_tags(message))
  end

  private

  def format_with_tags(message)
    tag_str = @tags.map { |t| "[#{t}]" }.join(" ")
    "#{tag_str} #{message}"
  end
end

# 使用
logger = TaggedLogger.new(Logger.new(STDOUT))
logger.tagged("RequestID:123", "User:456") do |tagged|
  tagged.info("Processing started")
  # => [RequestID:123] [User:456] Processing started
end
```

## 5. エラーメッセージの読み方

### よくあるエラーと対処

#### NoMethodError

```ruby
# エラー
undefined method `foo' for nil:NilClass (NoMethodError)

# 原因: nilに対してメソッドを呼んでいる
user = nil
user.name  # NoMethodError!

# 対処
user&.name           # nil safe navigation
user.name if user    # 明示的チェック
user || default_user # デフォルト値
```

#### NameError

```ruby
# エラー
undefined local variable or method `foo' for main:Object (NameError)

# 原因: 未定義の変数/メソッドを参照
puts undefined_variable

# 対処: 変数が定義されているか確認
defined?(variable)  # => nil or "local-variable"
```

#### ArgumentError

```ruby
# エラー
wrong number of arguments (given 1, expected 2) (ArgumentError)

# 原因: 引数の数が合わない
def add(a, b)
  a + b
end
add(1)  # ArgumentError!

# 対処: メソッドの定義を確認
method(:add).parameters  # => [[:req, :a], [:req, :b]]
```

#### TypeError

```ruby
# エラー
no implicit conversion of Integer into String (TypeError)

# 原因: 型の不一致
"Hello" + 1  # TypeError!

# 対処: 明示的な型変換
"Hello" + 1.to_s
```

#### LoadError

```ruby
# エラー
cannot load such file -- nonexistent (LoadError)

# 原因: ファイルが見つからない
require 'nonexistent'

# 対処
# 1. Gemがインストールされているか確認
# gem list | grep gem_name

# 2. パスを確認
$LOAD_PATH

# 3. require_relative を使用
require_relative 'lib/my_file'
```

### スタックトレースの読み方

```text
app.rb:10:in `method_c': divided by 0 (ZeroDivisionError)
  from app.rb:6:in `method_b'
  from app.rb:2:in `method_a'
  from app.rb:14:in `<main>'
```

```text
ファイル名:行番号:in `メソッド名': エラーメッセージ (例外クラス)
  from 呼び出し元ファイル:行番号:in `呼び出し元メソッド'
  ...
```

- 一番上がエラー発生箇所
- 下に行くほど呼び出し元
- `<main>` はトップレベル

## 9. よくあるバグと対処法

### nil 関連

```ruby
# 問題: nilで落ちる
users.first.name  # usersが空だとNoMethodError

# 対処1: safe navigation
users.first&.name

# 対処2: 明示的なチェック
if user = users.first
  user.name
end

# 対処3: デフォルト値
(users.first || NullUser.new).name
```

### 変数のスコープ

```ruby
# 問題: 変数が見えない
items.each do |item|
  result = process(item)
end
puts result  # NameError!

# 対処: ブロック外で定義
result = nil
items.each do |item|
  result = process(item)
end
puts result
```

### 破壊的メソッド

```ruby
# 問題: 意図せず元の配列が変更される
def process(items)
  items.sort!  # 元の配列も変更される
end

original = [3, 1, 2]
process(original)
puts original  # => [1, 2, 3]

# 対処: 非破壊的メソッドを使用
def process(items)
  items.sort  # 新しい配列を返す
end

# または明示的にコピー
def process(items)
  items.dup.sort!
end
```

### 浮動小数点の比較

```ruby
# 問題: 浮動小数点の誤差
0.1 + 0.2 == 0.3  # => false

# 対処: 許容誤差で比較
(0.1 + 0.2 - 0.3).abs < 0.0001  # => true

# または Rational を使用
Rational(1, 10) + Rational(2, 10) == Rational(3, 10)  # => true
```

### 文字エンコーディング

```ruby
# 問題: エンコーディングの不一致
str1 = "こんにちは".encode("UTF-8")
str2 = "世界".encode("Shift_JIS")
str1 + str2  # Encoding::CompatibilityError

# 対処: エンコーディングを統一
str1 + str2.encode("UTF-8")

# ファイル読み込み時
File.read("file.txt", encoding: "Shift_JIS:UTF-8")
```

### 並行処理

```ruby
# 問題: 競合状態
counter = 0
threads = 10.times.map do
  Thread.new do
    1000.times { counter += 1 }
  end
end
threads.each(&:join)
puts counter  # 10000にならない可能性

# 対処: Mutex を使用
mutex = Mutex.new
counter = 0
threads = 10.times.map do
  Thread.new do
    1000.times do
      mutex.synchronize { counter += 1 }
    end
  end
end
threads.each(&:join)
puts counter  # => 10000
```

## デバッグチェックリスト

1. **エラーメッセージを読む**
   - 例外クラス
   - エラーメッセージ
   - スタックトレース

2. **再現手順を確認**
   - 最小限の再現コードを作成
   - 入力データを確認

3. **仮説を立てる**
   - どこで問題が起きているか
   - 何が原因か

4. **デバッグ出力を追加**
   - p/pp で変数を確認
   - binding.irb/pry で対話的に調査

5. **テストを書く**
   - 失敗するテストを作成
   - 修正後にパスすることを確認

6. **ドキュメントを確認**
   - メソッドの仕様
   - 既知の問題

7. **最小限の修正**
   - 一度に1つの変更
   - 各変更後にテスト
